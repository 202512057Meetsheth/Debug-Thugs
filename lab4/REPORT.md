## Part A — Behavioural Rules

The five core behavioural rules derived directly from the production code (`part5.cpp` at `lab4-base`) are:

1. **Rule 1 (Wall Collision Termination):**  
   When the snake's head moves outside the grid boundaries (row $< 0$, row $\ge \text{rows}$, col $< 0$, or col $\ge \text{cols}$), the game terminates the snake's life by setting `alive = false`.

2. **Rule 2 (Self-Collision Termination):**  
   When the snake's head moves onto a coordinate currently occupied by any segment of its own body, the game terminates the snake's life by setting `alive = false`.

3. **Rule 3 (Normal Fruit Consumption, Growth & Scoring):**  
   When the snake's head moves onto the coordinates of a normal fruit (type 0), the snake retains its tail (increasing total length by 1) and increases the player's score by exactly 10 points.

4. **Rule 4 (180-Degree Direction Reversal Guard):**  
   When the snake is currently moving in a given direction, input corresponding to the exact opposite direction (e.g., LEFT when moving RIGHT) is rejected and does not update `pending_dir`.

5. **Rule 5 (Non-Overlapping Fruit Generation):**  
   When a new fruit is generated by `placeFruit()`, its coordinates are selected exclusively from vacant grid cells, never occupying a cell currently containing a snake segment or an obstacle.

## Part C — Coverage

### Attempted Coverage Command
```powershell
g++ --coverage -O0 -g part5.cpp tests/test_part_b.cpp -o tests.exe -std=c++11
```

### Why Direct Linking and Coverage Build Fails
1. **Multiple Definition of `main`:** Both `part5.cpp` (line 423) and `tests/test_part_b.cpp` define an entry point `main()`, causing a symbol collision at link time.
2. **Private-State & Private-Method Boundaries:** All member variables and step/placement routines in `CyberSnake` are declared under `private:`, preventing test code from directly invoking production functions.
3. **Terminal / Input Blocking:** The public entry point `CyberSnake::run()` calls `drawSplashThenWaitKey()` (line 394), which blocks unconditionally in a `while(true)` loop waiting for physical console keyboard input (`_getch()`). Automated test runners cannot drive execution through this path.

### Measured Coverage Result
* **Production Line Execution:** Effectively **0%**.
* **Production Branch Execution:** Effectively **0%**.
* **Coverage Assessment:** Meaningful production coverage was not obtainable from the un-seamed Part B suite because no production behavioural functions in `part5.cpp` could be executed by the test harness.

### Structural Coverage vs. Behavioural Verification
* **Structural Coverage (Code Coverage):** A purely syntactic metric measuring whether a line or branch instruction was executed by the CPU. High code coverage does not guarantee correctness—code can execute without any assertions, completely missing bugs or logical regressions.
* **Behavioural Verification:** A semantic specification verifying domain invariants (**Arrange-Act-Assert**). It guarantees that under specific preconditions, when an action is performed, the system transitions into the correct, expected state.

## Part D — Seam

* **Hardest Rule Selected:** **Rule 5** (*"Newly generated fruit never occupies a cell currently occupied by the snake or an obstacle."*)
* **Seam Kind:** **Object Seam** (Dependency Injection via Abstract Interface)
* **Abstract Interface:**
  ```cpp
  class IRandomSource {
  public:
      virtual ~IRandomSource() = default;
      virtual int getInt(int minVal, int maxVal) = 0;
  };
  ```
* **Production Implementation:**
  ```cpp
  class StandardRandomSource : public IRandomSource {
  public:
      StandardRandomSource() : rng((uint64_t)steady_clock::now().time_since_epoch().count()) {}
      int getInt(int minVal, int maxVal) override {
          uniform_int_distribution<int> dist(minVal, maxVal);
          return dist(rng);
      }
  private:
      std::mt19937_64 rng;
  };
  ```
* **Enabling Point:** `CyberSnake` constructor receives an optional `IRandomSource*` collaborator:
  ```cpp
  CyberSnake(IRandomSource* customRng = nullptr)
      : defaultRng(customRng ? nullptr : new StandardRandomSource()),
        rngSource(customRng ? customRng : defaultRng.get()) {
      init();
  }
  ```
* **Production Dependency Refactoring:**
  * Concrete `std::mt19937_64 rng` and hardware `steady_clock` seed moved behind `StandardRandomSource`.
  * `placeFruit()` and `maybeAddObstacle()` obtain all random values through `rngSource->getInt(min, max)`.
  * Normal production construction (`CyberSnake game;`) defaults to `StandardRandomSource`, preserving 100% of existing gameplay behaviour, distributions, neon aesthetics, and performance.

### Observability Limitation (Honest Architectural Audit)
* **What the Seam Provides:** The single `IRandomSource` seam provides deterministic control over the random integer values requested by `CyberSnake` and allows the test double (acting as a Spy) to inspect the query bounds (`empties.size() - 1`).
* **What the Seam Does NOT Provide:** Because `fruit.p`, `snake`, and `obstacles` remain `private:` members in `CyberSnake`, the single RNG seam does **not** provide direct read access to private coordinate fields.
* **Audit Statement:** The current test does **not** directly assert `fruit.p != s` for each snake segment or `fruit.p != o` for each obstacle. Instead, it verifies the collaborator query contract (proving that the candidate selection pool size equals total cells minus snake segments).
* **Why Rule 5 Remains the Part D Seam:** It successfully decouples the external non-deterministic collaborator (hardware epoch time / RNG entropy) with exactly one minimal seam and zero changes to player gameplay.

## Part E — Test Double

* **Test Double Used:** `DeterministicFakeRandomSource` (`tests/test_rule5.cpp`)
* **Taxonomy Classification:**
  * **Stub:** Returns predetermined, canned return values for `getInt(minVal, maxVal)` to ensure 100% repeatable execution.
  * **Spy:** Records the `(minVal, maxVal)` query parameters passed by `CyberSnake` into `recordedRanges` for assertion verification.
* **Nature of Interaction:**
  * **The collaborator is ASKED A QUESTION.**
  * `CyberSnake::placeFruit()` queries `IRandomSource`: *"Given that there are $N$ unoccupied candidate cells (range $[0, N-1]$), which index should be chosen?"*
  * The test double responds with a deterministic, preconfigured integer answer.
